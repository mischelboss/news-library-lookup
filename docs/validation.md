# Validation history

The diagnostic extension was verified to perform fresh searches from a Firefox background context and open returned articles through VÖBB. The homepage prototype was then tried in a real session with good behavior, without incorrect matches, omissions, or slow badges noticed at that point. This is informal acceptance evidence, not a measured accuracy study.

Automated regression checks cover title normalization, exact matches, ambiguity, short titles, wrong sources, unsafe document IDs, the date freshness guard (including recurring titles), queue deduplication, cache reuse, the 400-entry cap and TTL expiry, sender/frame validation, each failure category and its sanitized logging, cooldown, retry, reset during an in-flight request, request timeout, missing permissions, and pause behavior. A small purpose-built fake DOM runs `spiegel.js` against hand-written card markup to check paid-card detection, link-origin rejection, text-only rendering of remote metadata, late-inserted cards, and retry of failed badges only. `npm run check` also verifies the packaging allowlist. All of these use simulated responses and do not require credentials. A mutation spot check (disabling the freshness filter, epoch check, retry listener, cache cap, cooldown, origin check, frame check, and status count one at a time) was caught by the suite each time.

Page-level tests also check that every element id a page script uses exists in its HTML, that extension pages load only local scripts with no inline script, that the onboarding page opens once on a fresh install only, and that the onboarding permission button requests only the Genios origin. `npm run check` rejects a placeholder extension ID, a minimum Firefox version below 140, a missing data-collection declaration, a non-HTTPS update URL, and unlisted package files.

Not yet verified against the real service or in a real browser: the signed install flow and consent prompt, the onboarding page, the icon rendering, that Genios returns `ERSCHEINUNGSDATUM` in a format the freshness guard reads, that `/searchResult/Alle` opens correctly as the manual search link, and the real-browser behavior of the retry control. Check these after loading the extension.

A one-off offline browser check against downloaded Spiegel homepage HTML found 151 article cards and attached 47 paid-card badges. It checked same-tab links, absence of nested anchors, dynamic insertion, and pause/resume. That downloaded third-party HTML and the machine-specific browser harness are intentionally not committed. A portable fixture-based DOM suite remains future work.

CI verifies syntax, manifest resources, version alignment, deterministic regressions, and packaging. It does not verify authenticated browser operation, live publisher compatibility, matching accuracy, browser-store eligibility, or Genios licensing/usage permission.
